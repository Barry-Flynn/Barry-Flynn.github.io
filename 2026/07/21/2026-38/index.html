【Vibe Coding 技术分享】使用 VSCode + Claude Code + DeepSeek 打造高性价比 AI 编程环境

发表于2026-07-21|更新于2026-07-23
|字数总计:3.4k|阅读时长:11分钟|阅读量:

AI摘要：本文分享了在 VS Code 中用 Claude Code + DeepSeek 打造稳定 AI 编程环境的实战经验，重点讲解了为何选择 Claude Code、如何配置 DeepSeek API、以及配合 CC Switch 做协议桥接的关键细节。文章还分析了国内外 AI Agent 的生态差异、Claude Code 与 Codex 的适配区别，以及在中国使用时面临的账号、风控和兼容性问题。通过真实配置步骤和使用技巧，帮助读者快速上手 Claude Code 插件、避免常见坑，并最大化利用 DeepSeek 的上下文能力与模型性能。

说句题外话，我讨厌互联网上充斥着各种 AI Slop（AI 泔水），浏览博客文章或者教程帖子，如果被我发现疑似是 AI 写的，我会瞬间感到索然无味。我希望跟我分享技术的是真实的人，喜欢阅读用真实的手指在键盘上耗费真实的时间，所撰写出来的有着人味儿的文章，即便排版可能不是很规范，或者存在一些错别字。

01 什么是 Vibe Coding

Vibe Coding（氛围编程）作为一种全新的编程方式，早在 2025 年就悄然走红，简单来说就是：“不再用逐行手写代码的方式进行传统编程，而是用自然语言指挥 AI 写代码，你只负责审查”。本文不浪费过多笔墨介绍什么是 Vibe Coding [2]，互联网上已有很多Vibe Coding 教程 [3]，可以自行搜索学习。

Vibe Coding 工具有很多，有些工具的问世比 Vibe Coding 这个概念出现还要早，像早期的 GitHub Copilot 就是我大学期间的白月光，虽然现在早已丧失学生权益导致不能尽情享用，但至今依然在 VSCode 中尽量将其免费额度用光。后来我一直在 VSCode 中用的是阿里的“通义灵码”插件，它的行内补全功能让我在大学里就依赖上了，毕竟谁不想只输入几个字符就能通过 Tab 键直接补全好几行代码，它现在已更名为 Qoder，并且不能无限制使用了，免费额度少得可怜，逼我不得不“另寻新欢”。再到后来各种 AI IDE（如 Cursor 等），还有很多 AI Agent [1] 如雨后春笋般冒出，有些不再局限于编程，而是能通过调用各种工具操作电脑。

说着不浪费笔墨，实际写起文章来还是忍不住说一堆东西，现在进入正题吧。

多说一嘴，我现在属于 Vibe Coding 时代程序员流派中的轻度维新派，正在努力成为半维新派，争取早日迈入维新派的行列，不然就要变成喜欢手搓代码“古法编程”的落后于时代的小登了呜呜。（TvT）

02 为何选 Claude Code

简单列举一下目前市面上我有印象的 Agent 有哪些，真是让人看得眼花缭乱。

国外有 Claude Code、Codex、GitHub Copilot、Kilo Code、 OpenCode、Oh My OpenAgent (OmO/Oh My Opencode)、Pi、Oh My Pi、OpenClaw、Deep Code、Hermes、Reasonix 等；

国内有 WorkBuddy/CodeBuddy、Qoder、Trae、ZCode 等；

在目前各种 AI Agent 中，最火的就是 Anthropic 的 Claude Code，以及 OpenAI 的 Codex。

对于在中国的程序员来说，由于 Anthropic 极端反华，付费购买官方套餐会导致账号随时被封禁，并且不退钱，加之前段时间 Anthropic 被发现在 Claude Code 里植入隐蔽标记来区分中国用户 [4]，所以不推荐直接给他们送钱。实在想用 Claude 模型可以找便宜的 API 中转站，不过这里水很深，需要警惕站长跑路和模型掺水。

至于 OpenAI 的 Codex 的话（现在已合并至 ChatGPT），近期为了打击滥用行为，全面收紧账号风控，客户端登录会触发手机号验证，并且不支持发送中国大陆地区（+86）的短信。有人说在 ChatGPT 网页端开通 Plus 套餐会员后，再登录客户端就不弹手机号验证了，市场上也出现了帮人代开 Plus 会员的服务，但这没人能保证付费后一定不会再触发短信验证，也没人能保证 OpenAI 后期是否会封禁通过这种方式开通会员的账号。当然你可以通过接码平台的一次性号码临时解决这次验证，但如果下一次再让使用相同手机号接收验证码，还是无法继续使用。

山重水复疑无路，柳暗花明又一村。开源社区的 CC Switch 和 Codex++ 这样的工具，能够让 Agent 接入第三方大模型，这为通过低成本的 DeepSeek V4 Pro API 驱动 Claude Code 和 Codex 提供了可能。

由于新版的 Codex 默认走的是 OpenAI 的 Responses API，而国产模型几乎都只提供 OpenAI-compatible 的 Chat Completions，不兼容 Responses 格式。所以使用国产模型用于 Codex 的话需要，就得让 CC-Switch 作为本地代理工具充当协议翻译器 [5]：

  • 先把 Codex 发来的 Responses 格式请求改写成 Chat Completions 格式，再转发给上游模型；
  • 然后把上游返回的 SSE 流式响应重新封装成 Responses 格式，再回推给 Codex；
  • 需要处理 reasoning 字段、tool calls、previous_response_id 这些状态信息；

也正因为中间夹了这一层翻译，第三方模型在 Codex 里跑得稳不稳定不只取决于模型本身，还要看 provider 的协议兼容性以及代理实现的质量。

考虑到很多网友反应 DeepSeek 在 Codex 中的实际使用效果并没有原生 GPT 那样稳定，以及有人实测发现在 Claude Code 中接入 DeepSeek 的 KV Cache 缓存命中率（Cache Hit Rate）远高于 Codex [6-7]，并且我看到 DeepSeek API 对 Anthropic API 格式提供了支持以满足大家对 Anthropic API 生态的使用需求，所以我最终决定将 Claude Code 作为接下来一段时间要重点使用的智能体。

当然，如果有时间也会评测一下 OpenCode、Oh My Pi 和 Reasonix 的编程体验，但最近实在太忙了。

03 安装与配置

前置环境：电脑已安装 Node.js、VS Code、git

如果不仅想在 VS Code 中使用 Claude Code，还想在命令行里使用，为了提升安装速度，务必切换镜像源。

1. 安装并配置 Claude Code

本文仅涉及在 VS Code 中使用 Claude Code，不涉及 CLI 或桌面端的安装和使用。

点开 VS Code 侧边栏扩展，在应用商店搜索 Claude Code，然后安装有着 Anthropic 认证的、安装数量最多的 Claude Code for VS Code 插件。

安装完成后，打开插件设置。快速入口是在扩展列表或者扩展页面，点击小齿轮。

勾选 Disable Login Prompt 设置项，将不会在扩展中提示登录/授权。（在额外处理身份验证时使用）

找到 Environment Variables 设置项，它是启动 Claude 时要设置的环境变量，点击 在 settings.json 中编辑。（你也可以在 Claude 的 settings.json 中设置环境变量，参见文档 Claude Code 设置）

2. 充值并创建 API key

然后在 DeepSeek 开放平台 充值余额，在 API keys 页面创建 API key，复制并粘贴到上方 JSON 中。

请将此 API key 保存在安全且易于访问的地方。出于安全原因，你将无法通过 API keys 管理界面再次查看它。如果你丟失了这个 key，将需要重新创建。

温馨提示：不要将你的 API key 泄漏到公网中或发送给其他人，否则你的余额会被他人盗用。

保存并关闭 settings.json 编辑弹窗，然后点击 VS Code 右上角 Claude Code 的图标。

如果没要求登录，说明配置成功。（如果没有进入 Claude Code 的对话界面，可尝试重启 VS Code）

为了进一步确认，输入斜杠 / 或点击按钮打开命令菜单，点击 Switch model 切换模型，可以看到可用的 DeepSeek 模型列表。向模型发起对话，测试能否通讯，比如 你是什么模型？

一切正常！如果模型返回 API Error: 402 Insufficient Balance 说明余额不足，前往充值即可。

3. 安装并配置 CC Switch

CC Switch 是一款跨平台桌面应用，专为使用 AI 编程工具的开发者设计。它帮助你统一管理 Claude Code、Claude Desktop、Codex、Gemini CLI、OpenCode、OpenClaw 和 Hermes 等受管应用的配置。（了解更多内容可前往 CC Switch 文档 [12]）

前往 CC Switch 版本发布页面，展开 Assets 资源列表，Mac 用户推荐下载 macOS.dmg 安装包，Windows 用户推荐下载 Windows.msi 安装包。

  • CC-Switch-v3.18.0-macOS.dmg

  • CC-Switch-v3.18.0-Windows.msi

如果 Windows 安装时阻止了应用启动，展开“更多信息”，点击“仍要运行”即可。

安装完成后运行 CC Switch，在顶部选中 Claude Code 应用，然后点击右上角添加按钮。

在“添加新供应商”界面中，选中“预设供应商”中的 DeepSeek，然后填写 API Key。

在“高级选项”的“模型映射”中，给实际请求模型为 deepseek-v4-pro 的都勾选“声明支持1M”（用于给 Claude Code 的上下文能力声明），然后点击添加即可（你也可以勾选底部“配置 JSON”中的“最大强度思考”选项）。

添加成功后，鼠标悬浮于刚刚添加的供应商卡片上，点击右侧“检测连通”图标，正常情况下会显示“DeepSeek 连通正常”。

点击卡片右侧的“配置用量查询”图标，可以启用用量查询。

由于 CC Switch 的作用是直接创建和修改 用户目录/.claude/settings.json 全局配置文件，无论是 Claude Code 的命令行版和 VS Code 插件版，都会在启动时优先读取该文件。所以重启 VS Code 会发现，Claude Code 插件中的模型列表已随 CC Switch 切换，不再是我们刚才手动在 VS Code 里配置的环境变量里的模型映射名称了。（如果没有，在 CC Switch 的设置中，开启 通用 -> 窗口行为 -> 应用到 Claude Code 插件 即可）

04 权限模式与使用技巧

Claude Code 插件提供了四种权限模式：

  1. 手动模式（Manual）：Claude每次编辑前都会征求批准。
  2. 自动编辑（Edit automatically）：Claude将编辑您选择的文本或整个文件。
  3. 计划模式（Plan）：Claude将在编辑之前探索代码并提出计划。
  4. 自动模式（Auto）：Claude将批准通过安全检查的行动，并暂停任何有风险的行动。（自动为每个任务选择最佳权限模式）

当 Claude 想要编辑文件、运行 shell 命令或发起网络请求时，它会暂停并要求你批准该操作。

权限模式控制暂停发生的频率，你选择的模式决定了会话的流程：Manual 模式让你逐个审查每个操作，而更宽松的模式让 Claude 能够进行更长时间的不间断工作，并在完成后报告结果。对于敏感工作选择更多的监督，或在你信任工作方向时可以选择更少的中断。每种模式在便利性和监督之间做出不同的权衡。

更多功能用法和使用攻略可以浏览 CC Switch 官网 和 CC Switch 文档 自行探索。
